The user flow - is it good? What can be improved?
Yes, I think the flow is clear and easy to follow. Some things I noticed:

    When I park a vehicle with a wrong type (for example 9), the program asks for everything first and shows the error at the end. It is better to check each answer right away.
    When I write wrong input, I go back to the menu. It would be better to ask again.
    The menu comes directly after the result, so it is easy to miss the result. Maybe add an empty line or "Press Enter to continue".
    I can choose Populate garage many times. The second time nothing is added, because the sample cars are already in the garage. Maybe show a message like "Sample vehicles are already added", or remove option 2 from the menu after it has been used.

Error handling
Good, the program did not crash when I tested it. Some things I noticed:

    I tried 10000000000 as capacity. The message says "enter a positive whole number", and it is one, it is just too big for an int. Maybe show the range, like (1-1000)?
    When I chose Populate garage the second time, it said "Parked 0 of 3 vehicles." but not why. I looked in Garage.cs: AddVehicle() returns a good message (line 47), but Populate() only checks .Success and does not use the message. Maybe you can show the message for each vehicle that was not parked.
    Motorcycle, Airplane, Bus and Boat do not check their values. For example I can add an airplane with -3 engines.
    The properties have public set, so the values can be changed after the vehicle is parked.

Code separation (Logic vs UI vs Model)
I like how you separated the code. Garage has no Console code and the vehicles have their own folder. Some things I noticed:

    Garage uses LINQ (Enumerable.Repeat), but the assignment said no LINQ in Garage.
    The vehicle types are written in four places: the enum, the park menu text, the switch in ParkVehicle, and the search text. If you add a new type, you must remember to change all of them. You could build the menu and search text from the enum with Enum.GetValues(), so they always match.

Good job with the tests and comments!

User flow

    User flow is good and I didn't find any bugs while testing. Maybe something to think about is how the search is structured. While this isn't a bad implementation and is very straightforward for the user, you would probably need to present the search in a different way if more properties were added, so the user wouldn't need to go through a large amount of properties unrelated to their search.
