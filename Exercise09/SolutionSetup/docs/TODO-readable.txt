UI\ConsoleUI.Vehicles.cs
=====================================================================

[Prio:4, Effort:Medium, Impact:High] Split ParkVehicle into smaller methods
	ParkVehicle is about 50 lines: it prints the type menu, reads six values with inline
	lambdas, creates the vehicle and prints the result. Extract ReadVehicleType(),
	ReadRegistrationNumber(), ReadColor() and ReadParkingSize(typeInfo.Type) so ParkVehicle
	reads like a short list of steps. The try/catch for EndOfStreamException stays in ParkVehicle.

[Prio:3, Effort:Low, Impact:Medium] Share the "print vehicles" loop
	ListVehicles and PrintSearchResults (ConsoleUI.Search.cs) both loop over vehicles and
	write ToString(), each with its own "nothing found" message. One helper such as
	PrintVehicles(IReadOnlyList<IVehicle>, string emptyMessage) removes the duplicate.

[Prio:2, Effort:Low, Impact:Medium] Simplify the vehicle type parser lambda
	The lambda assigns "value = valid ? types[number - 1] : types[0]" just to satisfy the out
	parameter. Move it to a named method (TryParseVehicleType) so the intent is clear and the
	dummy fallback is hidden.

[Prio:1, Effort:Low, Impact:Low] Build VehicleTypes once in the constructor
	VehicleTypes uses a lazy "_vehicleTypes ??=" property. A readonly field set in the
	constructor is simpler to read. Note the lambdas use instance methods, so it has to be
	created after the fields are set.

[Prio:2, Effort:Medium, Impact:Medium] Make the Definitions table easier to read

Vehicles\Vehicle.cs and subclasses
=====================================================================

[Prio:3, Effort:Medium, Impact:Medium] Split the Vehicle constructor validation
	The constructor validates the registration number, wheels and parking size in one block
	with a tuple deconstruction in the middle. Extract ValidateParkingSize(...) and
	NormalizeRegistrationNumberOrThrow(...) so the constructor only assigns properties.

[Prio:2, Effort:Medium, Impact:Medium] Remove repeated subclass boilerplate
	Subclasses such as Boat repeat the same shape: Min/Max constants, a ThrowIfOutOfRange call
	with a description, unit and paramName, and a Details override. ThrowIfOutOfRange takes six
	arguments; consider an overload without unit for the common case, and check the other
	subclasses (Bus, Truck, Motorcycle, Airplane) for the same pattern.

[Prio:1, Effort:Low, Impact:Low] Make XML docs consistent
	Boat documents its constants but not Type, Details or the constructor, while Vehicle
	documents everything. Add short summaries so all vehicle classes follow the same style.
