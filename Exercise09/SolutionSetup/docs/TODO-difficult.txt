Garage\SearchCriteria.cs
=====================================================================

[Prio:4, Effort:Medium, Impact:High] Definitions table, object boxing and lambdas
	Each entry is a positional record with four lambdas. Parse returns "object?" and null means
	"invalid", so values are boxed and later unboxed with casts ((int)value, (IntRange)value).
	A cast mismatch only fails at runtime (InvalidCastException). Java/C++ developers may know
	generics but not this "untyped table + cast" trick. Idea: a generic Definition<T> that hides
	the casts. Also add a comment that Parse returning null is the "invalid" signal.

[Prio:4, Effort:Low, Impact:High] Nullable value types vs nullable reference types
	"int? NumberOfWheels" is Nullable<int> (a struct), "string? Color" is only an annotation.
	"text => int.TryParse(text, out int wheels) ? wheels : null" relies on a target-typed
	conditional (int and null become int?, then boxed to object?). This is a C# 9 feature with no
	direct Java/C++ equivalent. Unity projects often use older language versions.

[Prio:3, Effort:Low, Impact:Medium] Two Get overloads, "where T : struct"
	Get<T> (structs) and Get (string) differ only by the generic constraint. The constraint is what
	makes "T?" mean Nullable<T>. Rename to GetValue<T>/GetText, as already noted in TODO-readable.txt.

[Prio:2, Effort:Low, Impact:Medium] Property setters that remove entries
	Setting a property to null removes the filter (Set). Properties are therefore views over the
	_filters dictionary, not plain fields. Matches uses Find(filter.Key)! (null-forgiving operator).

Persistence\JsonGarageStorage.cs
=====================================================================

[Prio:4, Effort:Medium, Impact:High] async/await, await using, CancellationToken
	SaveAsync/LoadAsync use "await using" (async disposal of FileStream), FileOptions.Asynchronous
	and a CancellationToken with a default value. Unity developers usually know coroutines or
	UniTask rather than Task-based async. Explain what the await resumes on and why the stream is
	disposed before File.Move.

[Prio:3, Effort:Medium, Impact:Medium] Safe save sequence (temp file, .bak, move)
	Write temp -> copy old save to .bak -> move temp over save -> delete temp in finally. The
	reasons (no half-written save file) are not stated step by step. The finally block deletes
	the temp file only if the move did not already consume it.

[Prio:3, Effort:Low, Impact:Medium] Exception filters with pattern matching
	"catch (Exception ex) when (ex is IOException or UnauthorizedAccessException)" combines an
	exception filter (when) with the "or" pattern (C# 9). Different from Java multi-catch.

[Prio:2, Effort:Low, Impact:Low] Static JsonSerializerOptions and object initializer with collection
	"Converters = { new JsonStringEnumConverter() }" is a collection initializer on a property
	that is already created; it calls Add, it does not assign.

Garage\GarageHandler.cs
=====================================================================

[Prio:4, Effort:Low, Impact:High] Sync-over-async: .GetAwaiter().GetResult()
	SaveGarage and LoadGarage block on async methods because IHandler is synchronous. This is
	correct here (console app, no SynchronizationContext) but is a known deadlock risk in UI
	frameworks. Needs a comment explaining why it is acceptable, or make IHandler async.

[Prio:2, Effort:Low, Impact:Medium] Expression-bodied members and ?? throw
	RequireGarage uses "_garage ?? throw new ...". Many one-line "=>" members hide the
	InvalidOperationException contract; it is only visible in the class summary.

Garage\Garage.cs
=====================================================================

[Prio:3, Effort:Medium, Impact:Medium] Generic class with constraint and explicit interface implementation
	"Garage<T> : IEnumerable<T> where T : IVehicle" needs two GetEnumerator methods: one public
	generic and one explicit non-generic (IEnumerable.GetEnumerator). Java developers lack explicit
	interface implementation; C++ developers may expect templates without constraints.
	Also, "T?" on a type constrained only to an interface (FindByRegistration) is a nullable
	annotation, not Nullable<T>.

[Prio:2, Effort:Low, Impact:Medium] Collection expressions and primary-looking syntax
	"List<T> _vehicles = [];" and "List<string> failures = [];" use C# 12 collection expressions.
	The file also uses "is not null" and "static readonly int MaxCapacity" (not const, so it is
	not baked into callers at compile time).

[Prio:2, Effort:Low, Impact:Low] LINQ GroupBy/ToDictionary
	ListVehicleCountByType is a LINQ pipeline with deferred execution that is forced by ToDictionary.

Persistence\GarageMapper.cs

[Prio:3, Effort:Medium, Impact:Medium] Switch expressions with type patterns
	ToDto(IVehicle) uses "vehicle switch { Car car => ..., _ => throw ... }". Type patterns that
	declare variables and "throw" as an expression are new to Java/C++ developers. The order of
	arms matters if inheritance is added (more specific types first).

[Prio:3, Effort:Medium, Impact:Medium] Named arguments with optional record parameters
	"new VehicleDto(..., FuelType: car.FuelType)" skips the other optional parameters. Reading
	this requires knowing positional records and optional parameters (see VehicleDto.cs).

[Prio:2, Effort:Low, Impact:Medium] Required<T> helper
	"where T : struct" and "T?" make Required<T>(int?) return int. Unwraps Nullable<T> or throws.

UI\ConsoleUI.Helpers.cs
=====================================================================

[Prio:3, Effort:Medium, Impact:Medium] Custom delegate with out parameter, generic ReadValidated
	TryParser<T> exists because Func<> cannot have out parameters. Lambdas like
	"(string text, out int value) => int.TryParse(text, out value)" need explicit parameter types.
	ReadValidated<T> takes a prompt, a Func for the error text and a delegate; hard to follow
	at call sites. The "while (true)" loop exits only through return or exception.

[Prio:2, Effort:Low, Impact:Medium] TryParseFuelType
	Mixes a ternary, a null-coalescing "?? line", Enum.GetNames<T>() (generic, .NET 5+) and
	Enum.IsDefined. Split into named steps.

[Prio:2, Effort:Low, Impact:Low] EndOfStreamException as control flow
	ReadValidated throws when input ends; ReadLineOrEmpty returns "". Two different behaviours
	for end of input; document where the exception is caught.
